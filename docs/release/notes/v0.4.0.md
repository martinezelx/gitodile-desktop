# GitOdile 0.4.0

<!-- gitodile-highlights:start -->
## Highlights

- Connect GitHub, GitLab and Bitbucket accounts, including company GitHub and GitLab servers, browse their projects and choose which account clones, gets changes and publishes each project.
- Home finds and opens your projects or starts a clone from a pasted address, with a project switcher in the status bar, a calmer interface, monochrome official themes and a new crocodile and app icon.
- Overview predicts whether incoming changes overlap your work; one confirmation gets and combines non-overlapping changes with your unpublished versions and can publish too, keeping a recovery point first.
- Branches have their familiar name, group finished work for cleanup in one confirmed step with recovery points, and History shows local and published versions in foldable blocks with lanes for one branch or all of them.
- Console runs supported Git changes with confirmation by default and adds GitHub and GitLab shortcuts for requests, issues and CI; Settings shows Git's location and configuration and helps install or update gh and glab.

GitOdile 0.4.0 brings connected hosting accounts, a new Home launcher, safer
ways to combine project changes, branch cleanup and a calmer desktop interface.
It replaces the unpublished 0.3.1 candidate and includes the changes since 0.3.0.

## Accounts and cloning

- Connect GitHub and GitLab through their browser/CLI sessions or personal
  access tokens, and Bitbucket Cloud through API tokens. Native tokens are
  stored in the operating system's secure credential store without a plaintext
  fallback. Browser connections share the CLI's session and disclose its storage.
- Add GitHub Enterprise Server and GitLab Self-Managed company servers, with
  accounts kept separate by host. These connections are covered by fixtures;
  a real corporate server has not yet been qualified.
- Manage connections together in Settings → Accounts, check them on demand
  and see when a saved connection needs attention. Saved accounts are also
  verified in the background after launch.
- Choose a connection per project for HTTPS cloning, getting changes and
  publishing, without switching another project's account. Existing Git
  credential helpers remain an option, and SSH keeps using your configured keys.
- Browse account projects on GitHub, GitLab and Bitbucket, filter the current
  page and choose a destination in a two-screen clone flow. Pasting a supported
  hosting address checks read access with the selected connection before cloning.

## Home and everyday navigation

- Home replaces the old project-opening screen with a greeting and one launcher
  for recent and favourite projects, connected accounts and setup guidance.
  Enter continues the last project; a pasted folder opens it, a remote address
  prepares a clone, and a typed name can start a new project.
- Switching projects moves to the status bar, beside the current branch and its
  unsaved-work indicator. Its searchable popup also leads back to Home.
- Startup restores the previous project without flashing other screens.
  Overview gives more room to the next action, changed files and recent history,
  with scrolling detail cards and a layout that fits the window.
- The command palette grows from its search field in the status bar and keeps
  keyboard navigation. Branch switchers share a searchable, keyboard-accessible
  popup wherever they appear.

## Getting, publishing and recovering changes

- Overview forecasts whether getting project changes will advance the branch
  directly, need a merge version or overlap local work, before you start.
  One confirmation gets and combines changes that do not overlap, preserving
  unsaved edits even on other lines of the same incoming file.
- When publishing finds newer remote work, the same confirmation can get,
  combine and publish. A verified recovery point is kept first, together with
  a copy of combined unsaved content; merge hooks and commit signing are honoured.
  Real overlaps are refused with the affected files named.
- If the remote branch has been deleted, GitOdile explains what happened,
  offers the main branch and asks before publishing recreates the remote copy.
  Getting changes when nothing is newer finishes with a brief notice.
- Overview always offers stored discarded changes when any exist. Restore them
  in place from the picker; copies that cannot currently be restored stay
  visible with their reason instead of disappearing.
- The status bar brings remote state and the appropriate sync action together.

## Branches and history

- Branches are called Branches throughout the app, matching Git and other tools.
  Their list pins the current and main branches, then groups work in progress
  and finished work ready to clean up, with foldable name-prefix groups.
- Clean up several finished branches in one confirmed step, optionally removing
  their published copies. Each branch is checked again before deletion and
  gets a recovery point recording its name and last saved version. Results say
  which branches were deleted, kept or still have a remote copy.
- Branch details bring their actions, recent versions and route together, with
  renaming in place and reliable navigation to the selected branch's work.
- History separates local and published versions into foldable blocks. Expand
  a merge to see the versions it brought in on a thin lane, or show all branches
  at once. Pointing at a lane names its branch and where its work is included.

## Console, settings and updates

- Console no longer requires an advanced mode for supported Git changes.
  It previews and confirms them by default; Settings → Console → Confirm each
  change controls the question. Commands that rewrite history or can discard
  work remain unavailable.
- Six read-only shortcuts, `prs`, `my-prs`, `issues`, `runs`, `checks` and `repo`,
  query GitHub or GitLab through gh or glab using the CLI's own login. Help shows
  the command each runs, and the welcome identifies the project's provider.
- Settings shows where Git is installed, with copy and reveal actions and
  on-demand details for its configuration, credential helper, Git LFS and editor.
  Optional gh and glab have diagnostics and explicit installation/update actions
  on Windows, with official guidance on other platforms.
- Settings → Updates adds What's new and a manual download link. Update status,
  progress and cancellation remain reachable after closing the dialog, and a
  confirmed update finishes with a toast.

## Interface refinements

- Each project screen uses one readable sheet inside a quiet window frame.
  GitOdile's official light and dark themes use monochrome accents; community
  colour themes remain available.
- Dialogs, notifications, popups and notices share calmer surfaces and consistent
  headers. Toasts stack with visible lifetimes, and docked save/branch forms can
  close without losing drafts.
- GitOdile has a new flat crocodile and a white app icon. The Console mascot
  blinks in its welcome and becomes a faint watermark behind command output;
  reduced motion keeps it static.
- Diff search opens below its magnifier, long filenames no longer crowd controls,
  and image comparison keeps its divider aligned when image sizes differ.
  What's new keeps its title and close button visible while its notes scroll.
- React, Rust and Tauri tooling have been updated, including Tauri 2.12.3.

## Packages

- Windows is provided as an NSIS installer. Authenticode remains deferred, so
  Windows may show an unknown-publisher or SmartScreen warning.
- Linux is provided as an AppImage. macOS packages remain deferred.
- Both packages verify updates with the production Tauri updater key and use
  the public update feed. Publishing this release does not declare either
  target qualified.
