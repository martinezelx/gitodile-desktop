# GitOdile 0.2.0-preview.11

This testing preview reworks how updating looks and reads inside the app. It
is the first preview whose notes describe a user-facing change, and it is
intended as the installed starting point of a preview-to-preview update test
from 0.2.0-preview.10.

- Updates have their own section in Settings: the installed version, one
  status line, and the switch for the startup check. General no longer mixes
  application updates with the project-refresh options.
- The startup check is on by default. It asks GitHub once when the app opens
  (and again every 24 hours while it stays open), sends no project data and no
  installation identifier, and never downloads anything by itself. It can be
  turned off in Settings → Updates.
- A startup check that finds a newer version records a notification in the
  titlebar bell; its action opens the update dialog. Nothing is recorded when
  the app is already up to date.
- The update dialog shares What's new's shell, states the installed version
  before the offered one, and shows a single explanation when something fails.
  What's new keeps "Check for updates" as a footer action under the local notes.
- Update copy is shorter and no longer repeats the product name, in both
  English and Spanish.
- What's new lists every release's highlights, newest first, and keeps the
  older ones; earlier previews with nothing user-facing are left out of the
  list.
- Windows is provided as an NSIS installer. Authenticode remains deliberately
  deferred, so Windows may show an unknown-publisher or SmartScreen warning.
- Linux is provided as an AppImage.
- Both packages verify updates with the production Tauri updater key and the
  public `preview.json` feed in `martinezelx/gitodile`.
- macOS remains disabled and no macOS package is included.

Publishing this preview does not declare either target qualified and does not
authorize stable publication.
