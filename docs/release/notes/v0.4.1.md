# GitOdile 0.4.1

## Highlights

- Connect Azure Repos with an organization's personal access token, and see every connected GitHub, GitLab and Bitbucket account with its own profile picture.
- Changes previews Markdown files as one readable document with removed and added blocks marked, and steps between them; long wrapped diff lines no longer overlap.
- Notifications stay in a quiet inbox across restarts: opening it reads nothing, and each notice can be marked read, unread or removed on its own.
- Settings is reorganized with a Language and region section, and every screen now shares the same icons, spacing, focus ring and selection, so the app reads as one piece.
- GitOdile starts with a fifth less JavaScript, scrolls long diffs more smoothly, and keeps your selected file, version, branch and scroll when you come back to a screen.

GitOdile 0.4.1 adds Azure Repos and account pictures, a readable Markdown
preview, a quiet notification inbox, a reorganized Settings and a more
consistent interface, and it starts faster.

## Accounts and cloning

- Connect Azure Repos with a personal access token scoped to one Azure DevOps
  organization. The token is checked and stored in the operating system's
  secure credential store per organization, Git receives it only for that
  organization's addresses, and Settings, Home and Clone offer it beside the
  other providers. Repository browsing and Microsoft browser sign-in are not
  included yet, and live Azure transfers have not been qualified.
- Connected GitHub, GitLab and Bitbucket accounts, including company servers,
  show the profile picture their provider holds, with the provider's mark at
  the corner. Pictures are fetched without credentials from the provider's own
  hosts, cached on this computer, refreshed when an account is checked and
  deleted when it is removed or signed out. Gravatar is never contacted.
- Saved versions show their author's initials, yours included.

## Changes and History

- Markdown files in Changes open as a preview by default: the saved and current
  documents merge into one, with removed and added blocks marked and arrows to
  step between them. Very large documents show their changed fragments, clearly
  marked as partial. The preview is read-only and never loads images, runs HTML
  or follows links.
- Long diff lines that wrap no longer paint over the line below after the pane
  changes width, and diffs are drawn in the code font chosen in Settings.
- Returning to Changes, History or Branches keeps the selected file, version or
  branch, the folded folders and the scroll position. Screens appear without an
  entry animation, and file lists start in folder view.

## Notifications

- The notification panel is a silent inbox of up to 50 entries that survives
  restarts. Opening, pointing at or scrolling it marks nothing as read; each
  notice has its own read and remove controls, and "Mark all as read" sits
  beside "Clear all".
- An automatic check that repeats the same news keeps its place and its time
  instead of arriving again.

## Settings and windows

- Settings groups its sections into App, Work and Version control. Language and
  date formats move to a new Language & region section, where each language is
  a card written in that language, and a language change fades the window like
  a theme change. Line endings join the Git section.
- Navigation explains every destination, its arrows appear on hover or focus,
  and Restore default resets both which destinations show and their order.
  Theme, font and icon pickers share one selected state.
- On macOS, GitOdile uses the system's window controls and moves the overflow
  menu's entries into a native menu bar. Windows and Linux are unchanged. This
  has not yet been validated on a Mac.
- Pressing the titlebar now closes any open menu, popup, calendar or filter
  list, and the account row in the titlebar menu stays on one line.

## A more consistent interface

- Icons, spacing, focus rings, selected rows, notices, disabled controls, small
  icon buttons and empty states now follow one set of sizes and strengths, so
  the same kind of thing looks the same on every screen.
- The status bar gives the project and branch names room before the search
  field, so both read in full in a window of about 1,100 pixels.

## Performance

- Launch loads about 20% less JavaScript: only the active language's text is
  loaded, and the Markdown preview loads with Changes rather than at startup.
- Scrolling a diff no longer re-highlights every visible line on each frame.
- Opening a project and refreshing its status start fewer Git processes.
- Dependencies are updated to their latest compatible versions.

## Packages

- Windows is provided as an NSIS installer. Authenticode remains deferred, so
  Windows may show an unknown-publisher or SmartScreen warning.
- Linux is provided as an AppImage. macOS packages remain deferred.
- Both packages verify updates with the production Tauri updater key and use
  the public update feed. Publishing this release does not declare either
  target qualified.
